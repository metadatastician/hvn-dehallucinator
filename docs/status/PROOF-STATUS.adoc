= Proof status — hvn-dehallucinator
:revdate: 2026-11-09
:toc: preamble

Each row names the artefact that discharges it. Statuses are the closed
vocabulary of standards PROOF-POLICY §5: PROVEN (a kernel-checked proof, no
escape hatch), PROVEN-WITH-AXIOMS (kernel-checked, resting on named axioms),
TESTED (an executable check on a bounded or sampled domain, with its bounds),
ASSUMED (a stated hypothesis, or a transcription no kernel checked) and OPEN
(not done). A status moves only
with a named module, lemma, fixture or log line. `scripts/check-proof-status.sh`
refuses this file if a row that is not OPEN names a path or a fragment that is
not in the tree.

== Where things stand

The engine's guarantee is *tested* against the engine itself and *proved*
against a model of it. The guarantee is only as strong as the measurement
under it. That is a stated assumption, HD-A: the verifier counts the bound
target's surviving artefacts correctly. Three suites run on every pull
request (Engine Guarantee workflow). Each can fail and has been watched
failing:

* the guarantee suite: COMPLETE only from a measured zero of the target bound
  at the baseline, no caller-asserted progress, no caller-chosen target,
  regression, the attempt budget, strict state parsing;
* the witness suite: the blind-spot witness on regress and refuse, with the
  2026-08-23/24 Incident replayed at its literal numbers;
* the hardening suite: root finding, parsing, verifier failures, pruning.

On 2026-11-09 a review found a hole the suites had not tested. `update <dir>`
measured whatever directory the caller named. A caller could therefore point
it at an empty directory and get a measured zero, so COMPLETE, for a target
that still held work. The engine now binds the target when the baseline is
set (`init <n> <target>`, `init-from <target>`). `update` and `verify` take no
argument and measure only that target. The state file records the target on a
fifth line. The TLA+ model has the old behaviour as a negative control that
TLC must refute (HD-1T).

In the Agda kernel, `EngineCore.agda` models every command of `Engine.hs` and
proves THE GUARANTEE in that model: no command introduces COMPLETE except an
update whose reading is a counted zero. It also proves the budget and
completed-count invariants and the breaker's behaviour. `Fibre.agda` proves the
epistemic core: the recorded state alone does not identify what remains, and
COMPLETE needs an inhabited measured case. A TLA+ model, checked by TLC, puts
the engine against a world that changes freely and a verifier that can fail.
At its bounds it finds no violation. It does find the Incident in the original
engine, and a false COMPLETE when the caller chooses the target. A
differential test ties these models to `Engine.hs` on 3,186 recorded engine
traces (HD-F-E, TESTED; not a proof). These three engine developments are
engineering under PROOF-POLICY §1, and are recorded §4 exceptions (below).

Haruspex runs the same check before a prompt is sent. It is a *theory*
development: an Agda checker over a declared finite schema (`Haruspex.agda`,
HD-H). The checker is total and makes no model call, and every output is
sound for the readings the schema lists. On the certified finite checker's own
model it decides exactly what that checker decides. Nothing yet runs it on
real prompts (HD-H-R, OPEN). Its Rocq and Lean recheck legs are re-proved with no axioms
(HD-H-RL); their statement correspondence waits on the owner's review, so its grade
under PROOF-POLICY §8 is PWG-3 for now (below).
The proof files inherited from the template are not claims about this project;
HDH-02 (#29) tracks them.
